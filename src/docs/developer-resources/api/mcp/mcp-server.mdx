The Augno MCP server, `@augno/sdk-mcp`, exposes the Augno API to AI agents and assistants through the [Model Context Protocol](https://modelcontextprotocol.io) (MCP). Once connected, an agent in a client like Claude, Cursor, or your own MCP-aware app can read and write Augno data on your behalf — authenticated with your <InternalLink pathKey="api.apiKeys" text="API key" /> and bounded by that key's permissions.

It wraps the <InternalLink pathKey="api.typescriptSdk" text="TypeScript SDK" /> (`@augno/sdk`), so everything the SDK can do, an agent can do.

## How it works

Rather than generating one tool per endpoint — which floods an agent's context with hundreds of tools — the server exposes a single **`execute`** tool that runs short TypeScript snippets against a pre-authenticated Augno SDK client. The agent writes code; the server runs it and returns the result.

The code runs in a sandboxed runtime **inside the server** — there is no third-party execution environment, and the sandbox can only reach the Augno API. This keeps your data and credentials within the boundary you connect to.

> **What the agent can do is exactly what your API key can do.** The MCP server forwards your key on every call; it grants no extra access. Scope keys narrowly and prefer a dedicated key per integration. See <InternalLink pathKey="api.apiKeys" text="API keys" /> for how to create and limit them.

## Authenticate

The server authenticates to the Augno API with your API key, passed as a bearer token. Provide it as the `AUGNO_API_KEY` environment variable (local servers) or as an `Authorization: Bearer <key>` header (remote servers). The key determines which account the agent operates on, so no separate account selection is required.

You do not need to set the `Augno-Version` header yourself — the server pins the API version it was built against and sends it automatically. See <InternalLink pathKey="api.versioning" text="API versioning" />.

## Connect a client

The MCP server is hosted at `https://mcp.augno.com`. Connect to it over HTTP — there's nothing to install — or run a **local** server over stdio if you prefer. Either way, authenticate with your API key. Setup for Cursor and Claude Code is below.

<DocTabs className="my-4">
<DocTab label="Cursor">

Cursor reads MCP servers from `~/.cursor/mcp.json` (all projects) or `.cursor/mcp.json` in a project. Add an `augno` entry, then enable it under **Settings → MCP** (a green dot means it connected).

**Hosted (HTTP):**

```json
{
    "mcpServers": {
        "augno": {
            "url": "https://mcp.augno.com",
            "headers": {
                "Authorization": "Bearer YOUR_API_KEY"
            }
        }
    }
}
```

**Local (stdio):** runs the server on demand with `npx`.

```json
{
    "mcpServers": {
        "augno": {
            "command": "npx",
            "args": ["-y", "@augno/sdk-mcp"],
            "env": {
                "AUGNO_API_KEY": "YOUR_API_KEY"
            }
        }
    }
}
```

</DocTab>
<DocTab label="Claude Code">

Add the server with the `claude mcp` CLI.

**Hosted (HTTP):**

```sh
claude mcp add --transport http augno https://mcp.augno.com \
  --header "Authorization: Bearer YOUR_API_KEY"
```

**Local (stdio):** everything after `--` is the command Claude Code runs.

```sh
claude mcp add --env AUGNO_API_KEY=YOUR_API_KEY augno -- npx -y @augno/sdk-mcp
```

By default the server is saved for the current project only. Add `--scope user` to make it available in every project, or `--scope project` to write a shared `.mcp.json` your team can commit:

```json
{
    "mcpServers": {
        "augno": {
            "type": "http",
            "url": "https://mcp.augno.com",
            "headers": {
                "Authorization": "Bearer YOUR_API_KEY"
            }
        }
    }
}
```

Verify the connection with `claude mcp list` (or `/mcp` inside a session), and remove it with `claude mcp remove augno`.

</DocTab>
</DocTabs>

> Treat your API key like a password: load it from a secret store or your shell environment, never commit it, and never expose it to a browser. For a shared `.mcp.json`, reference an environment variable rather than pasting the key inline.

## The `execute` tool

The agent calls `execute` with a `code` snippet. The snippet must define a top-level `run` function whose single parameter is the Augno SDK client:

```ts
async function run(client) {
    const items = await client.catalog.items.list();
    return items.data.map((item) => ({ id: item.id, name: item.name }));
}
```

The server runs `run`, awaits the result, and returns it to the agent as JSON. The `client` is a fully-typed `Augno` instance — the same one documented in the <InternalLink pathKey="api.typescriptSdk" text="TypeScript SDK" /> guide — so the agent can call any endpoint, paginate, and compose multiple calls in one snippet:

```ts
async function run(client) {
    const customer = await client.sales.customers.create({
        name: 'Acme Co.',
    });
    const orders = await client.sales.salesOrders.list({ customer_id: customer.id });
    return { customerId: customer.id, orderCount: orders.data.length };
}
```

Errors thrown by the SDK (a `4xx`/`5xx` response, a connection failure) are returned to the agent as the tool result so it can react or retry.

## Good practices

- **Use a dedicated, least-privilege key.** The agent inherits the key's permissions exactly. A read-only key keeps an assistant from making changes.
- **Rotate keys** used by long-lived assistants, and revoke any key that may have been exposed.
- **Review what the agent ran.** Each underlying API call appears in your <InternalLink pathKey="api.overview" text="request logs" /> with a request ID, so you can audit agent activity.
