Every OpenMRP API error uses the same response envelope. The most important fields are `code`, `type`, and `is_transient`: use those fields for programmatic handling instead of parsing the human-readable `message`.

This page is organized as a quick reference first, then a troubleshooting guide by category. Each error code has a stable anchor, so links like `https://docs.openmrp.ai/api/errors#validation_failed` open the matching card.

## Error Envelope

All error responses are wrapped in an `error` object:

```json
{
    "error": {
        "code": "validation_failed",
        "type": "invalid_request_error",
        "message": "The email address is not valid.",
        "param": "email",
        "doc_url": "https://docs.openmrp.ai/api/errors#validation_failed",
        "is_transient": false,
        "quota": null,
        "request_log_url": "https://openmrp.ai/dashboard/request-logs/rq_fbv1ygmybo3eauykr74"
    }
}
```

| Field             | Type           | How to use it                                                                                         |
| ----------------- | -------------- | ----------------------------------------------------------------------------------------------------- |
| `code`            | string         | Exact machine-readable error condition. Branch on this for client behavior.                           |
| `type`            | string         | Broad category: `invalid_request_error`, `api_error`, or `idempotency_error`.                         |
| `message`         | string         | Human-readable explanation. Safe to display, but not stable enough to parse.                          |
| `param`           | string \| null | Offending request field or parameter when OpenMRP can identify one.                                     |
| `doc_url`         | string         | Documentation link for this error. Usually follows `https://docs.openmrp.ai/api/errors#{code}`.        |
| `is_transient`    | boolean        | Whether retrying the same operation may succeed after a delay.                                        |
| `quota`           | object \| null | Present only for `limit_exceeded`; contains `limit`, `used`, and `reset_at`.                          |
| `request_log_url` | string \| null | Dashboard link for the request log when one is available. Include this when contacting OpenMRP support. |

## Handling Strategy

| Type                    | Meaning                                                                                         | Default action                                                                |
| ----------------------- | ----------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------- |
| `invalid_request_error` | The request cannot be completed as sent. Examples: bad input, auth, permissions, or not found.  | Fix the request, credentials, account, or resource state before retrying.     |
| `api_error`             | OpenMRP or a dependency failed while handling a valid request.                                    | Retry only when `is_transient` is `true`; use exponential backoff and jitter. |
| `idempotency_error`     | A mutation key is already in use, or the same key was reused with different request parameters. | Retry the same operation only for `idempotency_in_progress`.                  |

For mutating requests, include an idempotency key. If a retry is needed, reuse the same key for the same operation so OpenMRP can avoid duplicate side effects.

## Troubleshooting Guide

The cards below include a representative request, expected error response, and the recommended fix. Example IDs, account IDs, and request log URLs are placeholders; the routes and the `message` strings are the real ones the API uses.

### Authentication & Authorization

These errors mean OpenMRP could not authenticate the caller, or the authenticated caller is not allowed to perform the operation. See <DocLink pathKey="api.apiKeys">API Keys</DocLink> for more about API key setup and rotation.

<ErrorDetails code="expired_token" meta="401 Unauthorized, not transient">

A JWT access token or refresh token has passed its expiry. Retrying with the same token will keep failing.

This is a session-token error, not an API key error. Access tokens travel in the `__Secure-openmrp.access-token` cookie, so this code comes from browser-style session traffic — never from a `Authorization: Bearer mrp_sk_…` call. In production, sending an access token in the `Authorization` header is rejected.

```bash
curl API_HOST/v1/catalog/items \
  -H "Cookie: __Secure-openmrp.access-token=EXPIRED_ACCESS_TOKEN" \
  -H "OpenMRP-Version: CURRENT_API_VERSION" \
  -H "OpenMRP-Account: YOUR_ACCOUNT_ID"
```

```json
{
    "error": {
        "code": "expired_token",
        "type": "invalid_request_error",
        "message": "Token has expired.",
        "param": null,
        "doc_url": "https://docs.openmrp.ai/api/errors#expired_token",
        "is_transient": false,
        "quota": null,
        "request_log_url": "https://openmrp.ai/dashboard/request-logs/rq_fbv1ygmybo3eauykr74"
    }
}
```

An expired refresh token reports `Refresh token has expired.` under the same code.

Refresh the session if your client has a refresh flow, or ask the user to sign in again. Server-to-server integrations should use an API key instead of a session token — API keys never produce this code.

Because access tokens are short-lived, this code is routine background noise rather than a real failure. The dashboard's request-log view hides it by default; the API equivalent is `exclude_error_codes=expired_token`.

</ErrorDetails>

<ErrorDetails code="api_key_expired" meta="401 Unauthorized, not transient">

The API key has passed its configured expiration date.

```bash
curl API_HOST/v1/catalog/items \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "OpenMRP-Version: CURRENT_API_VERSION" \
  -H "OpenMRP-Account: YOUR_ACCOUNT_ID"
```

```json
{
    "error": {
        "code": "api_key_expired",
        "type": "invalid_request_error",
        "message": "API key has expired.",
        "param": null,
        "doc_url": "https://docs.openmrp.ai/api/errors#api_key_expired",

        "quota": null,
        "request_log_url": "https://openmrp.ai/dashboard/request-logs/rq_fbv1ygmybo3eauykr74"

```

Create a new API key, deploy it to the integration, and remove the expired key from secret stores or environment variables.

</ErrorDetails>

The API key was explicitly revoked by an administrator or by OpenMRP. Revocation is immediate and permanent.

```bash
curl API_HOST/v1/catalog/items \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "OpenMRP-Version: CURRENT_API_VERSION" \
  -H "OpenMRP-Account: YOUR_ACCOUNT_ID"
```

```json
{
    "error": {
        "code": "api_key_revoked",
        "type": "invalid_request_error",
        "message": "API key has been revoked.",
        "param": null,
        "doc_url": "https://docs.openmrp.ai/api/errors#api_key_revoked",

        "request_log_url": "https://openmrp.ai/dashboard/request-logs/rq_fbv1ygmybo3eauykr74"

}
```

Generate a replacement key with the required permissions and audit any services that may still be using the revoked key.

</ErrorDetails>

<ErrorDetails code="invalid_credentials" meta="401 Unauthorized, not transient">

The credentials are missing, unknown, or not valid for the way they were presented. The message names the specific problem; the code is the same for all of them.

```bash
curl API_HOST/v1/catalog/items \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "OpenMRP-Version: CURRENT_API_VERSION" \
  -H "OpenMRP-Account: YOUR_ACCOUNT_ID"
```

```json
{
    "error": {
        "code": "invalid_credentials",
        "type": "invalid_request_error",
        "message": "Invalid API Key provided: mrp_sk_prod_UN****c123.",
        "param": null,
        "doc_url": "https://docs.openmrp.ai/api/errors#invalid_credentials",
        "is_transient": false,
        "quota": null,
        "request_log_url": "https://openmrp.ai/dashboard/request-logs/rq_fbv1ygmybo3eauykr74"
    }
}
```

</ErrorDetails>

<ErrorDetails code="insufficient_permissions" meta="403 Forbidden, not transient">

The caller is authenticated but lacks the permission required for the operation.

```bash
curl -X PATCH API_HOST/v1/identity/account-users/acus_e5zu8bde0z3h \
  -H "Authorization: Bearer READ_ONLY_API_KEY" \
  -H "OpenMRP-Version: CURRENT_API_VERSION" \
  -H "OpenMRP-Account: YOUR_ACCOUNT_ID" \
  -H "Content-Type: application/json" \
  -d '{"name":"Dana Smith"}'
```

```json
{
    "error": {
        "code": "insufficient_permissions",
        "type": "invalid_request_error",
        "message": "This API Key does not have permission to team:update",
        "param": null,
        "doc_url": "https://docs.openmrp.ai/api/errors#insufficient_permissions",
        "is_transient": false,
        "quota": null,
        "request_log_url": "https://openmrp.ai/dashboard/request-logs/rq_fbv1ygmybo3eauykr74"
    }
}
```

The message names the `domain:action` permission the caller is missing, so it tells you exactly what to grant. Use an actor or API key with the required role, grant the missing permission, or verify that `OpenMRP-Account` points at an account the caller can access.

</ErrorDetails>

<ErrorDetails code="payment_required" meta="402 Payment Required, not transient">

The account's subscription is `past_due`, `canceled`, or `unpaid`.

```bash
curl API_HOST/v1/catalog/items \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "OpenMRP-Version: CURRENT_API_VERSION" \
  -H "OpenMRP-Account: YOUR_ACCOUNT_ID"
```

```json
{
    "error": {
        "code": "payment_required",
        "type": "invalid_request_error",
        "message": "Your subscription is past_due. Please update your billing information to continue.",
        "param": null,
        "doc_url": "https://docs.openmrp.ai/api/errors#payment_required",
        "is_transient": false,
        "quota": null,
        "request_log_url": "https://openmrp.ai/dashboard/request-logs/rq_fbv1ygmybo3eauykr74"
    }
}
```

Resolve the billing issue in <DocLink pathKey="manageAccount.plansAndBilling">Plans & billing</DocLink>, confirm the subscription is active, and retry.

</ErrorDetails>

<ErrorDetails code="agent_spending_cap_reached" meta="402 Payment Required, not transient">

The account has a monthly agent spending cap configured and the current period's spend has reached it, so an agent run was refused.

Raise or clear the **Monthly Spending Limit** under **AI Spending** in <DocLink pathKey="manageAccount.plansAndBilling">Plans & billing</DocLink>, or wait for the next billing period. Re-triggering without changing the cap produces the same outcome.

</ErrorDetails>

### Limits

Limits are plan or registration capacity problems. They are not the same as rate limits.

<ErrorDetails code="limit_exceeded" meta="403 Forbidden, not transient">

The account reached a plan-imposed resource limit. The `quota` object provides the current limit, usage, and optional reset time.

```bash
curl -X POST API_HOST/v1/core/sandboxes \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "OpenMRP-Version: CURRENT_API_VERSION" \
  -H "OpenMRP-Account: YOUR_ACCOUNT_ID" \
  -H "Content-Type: application/json" \
  -d '{"name":"West Coast Sandbox","mode":"seeded"}'
```

```json
{
    "error": {
        "code": "limit_exceeded",
        "type": "invalid_request_error",
        "message": "Maximum of 5 sandbox accounts per account reached.",
        "param": null,
        "doc_url": "https://docs.openmrp.ai/api/errors#limit_exceeded",
        "is_transient": false,
        "quota": {
            "limit": 5,
            "used": 5,
            "reset_at": null
        },
        "request_log_url": "https://openmrp.ai/dashboard/request-logs/rq_fbv1ygmybo3eauykr74"
    }
}
```

Delete unused resources, wait until `reset_at` when present, or upgrade the account's plan.

</ErrorDetails>

<ErrorDetails code="registration_closed" meta="403 Forbidden, not transient">

We have limited capacity for some plans, so you may encounter an error when attempting to join a particular plan.
```json
{
    "error": {
        "code": "registration_closed",
        "type": "invalid_request_error",
        "message": "Registration for the starter plan is currently at capacity.",
        "param": null,
        "doc_url": "https://docs.openmrp.ai/api/errors#registration_closed",
        "is_transient": false,
        "quota": null,
        "request_log_url": "https://openmrp.ai/dashboard/request-logs/rq_fbv1ygmybo3eauykr74"
    }
}
```

Choose a plan that still has capacity, wait for capacity to reopen, or contact OpenMRP support if this plan should accept new registrations.

</ErrorDetails>

### Validation

Validation errors mean the request body or method is not acceptable for the endpoint.

<ErrorDetails code="validation_failed" meta="400 Bad Request, not transient">

The request was parsed and structurally valid, but a business rule rejected it. This is the catch-all validation code: field-shape problems get the more specific codes below, and anything an endpoint refuses for domain reasons lands here.

```bash
curl -X DELETE API_HOST/v1/operations/shipping-terms/shtm_c5gxy05whw6r \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "OpenMRP-Version: CURRENT_API_VERSION" \
  -H "OpenMRP-Account: YOUR_ACCOUNT_ID"
```

```json
{
    "error": {
        "code": "validation_failed",
        "type": "invalid_request_error",
        "message": "Default shipping terms cannot be deleted.",
        "param": null,
        "doc_url": "https://docs.openmrp.ai/api/errors#validation_failed",
        "is_transient": false,
        "quota": null,
        "request_log_url": "https://openmrp.ai/dashboard/request-logs/rq_fbv1ygmybo3eauykr74"
    }
}
```

The same code is returned when more than one body field fails validation at once. In that case `message` concatenates the individual field messages (`Validation failed for the following fields: …`) and `param` names the first offending field.

Fix the value named by `param` when there is one, validate request bodies before sending, and retry with corrected input.

</ErrorDetails>

<ErrorDetails code="missing_field" meta="400 Bad Request, not transient">

A required JSON body field was omitted.

```bash
curl -X POST API_HOST/v1/catalog/units \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "OpenMRP-Version: CURRENT_API_VERSION" \
  -H "OpenMRP-Account: YOUR_ACCOUNT_ID" \
  -H "Content-Type: application/json" \
  -d '{"name":"Gram","type":"mass","ratio_numerator":"1","ratio_denominator":"1","offset_numerator":"0","offset_denominator":"1"}'
```

```json
{
    "error": {
        "code": "missing_field",
        "type": "invalid_request_error",
        "message": "Field 'abbreviation' is required.",
        "param": "abbreviation",
        "doc_url": "https://docs.openmrp.ai/api/errors#missing_field",
        "is_transient": false,
        "quota": null,
        "request_log_url": "https://openmrp.ai/dashboard/request-logs/rq_fbv1ygmybo3eauykr74"
    }
}
```

Add the required field shown in `param`. Required fields cannot be cleared with JSON `null`.

</ErrorDetails>

<ErrorDetails code="invalid_format" meta="400 Bad Request, not transient">

A body field is present, but its value does not match the format or constraint the endpoint accepts.

```bash
curl -X POST API_HOST/v1/catalog/units \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "OpenMRP-Version: CURRENT_API_VERSION" \
  -H "OpenMRP-Account: YOUR_ACCOUNT_ID" \
  -H "Content-Type: application/json" \
  -d '{"name":"Gram","abbreviation":"g","type":"mass","ratio_numerator":"1","ratio_denominator":"0","offset_numerator":"0","offset_denominator":"1"}'
```

```json
{
    "error": {
        "code": "invalid_format",
        "type": "invalid_request_error",
        "message": "Field 'ratio_denominator' must not be zero.",
        "param": "ratio_denominator",
        "doc_url": "https://docs.openmrp.ai/api/errors#invalid_format",
        "is_transient": false,
        "quota": null,
        "request_log_url": "https://openmrp.ai/dashboard/request-logs/rq_fbv1ygmybo3eauykr74"
    }
}
```

A JSON type mismatch in the **body** reports the same code with a decoder-level message — sending `"ratio_numerator": 1` instead of the string `"1"` on the request above yields `Invalid type for field 'ratio_numerator': expected string, got number`. Explicit `null` on a field that cannot be cleared reports `Field 'name' cannot be null.` A bad query parameter is a [`parameter_invalid`](#parameter_invalid) instead.

Normalize the field into the format shown in the endpoint reference. Use public type IDs exactly as returned by the API.

</ErrorDetails>

<ErrorDetails code="method_not_allowed" meta="405 Method Not Allowed, not transient">

The route exists, but does not support the HTTP method you used.

```bash
curl -X POST API_HOST/v1/catalog/items/it_pej07ckhvu62 \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "OpenMRP-Version: CURRENT_API_VERSION" \
  -H "OpenMRP-Account: YOUR_ACCOUNT_ID"
```

```json
{
    "error": {
        "code": "method_not_allowed",
        "type": "invalid_request_error",
        "message": "Method POST not allowed for path /v1/catalog/items/it_pej07ckhvu62.",
        "param": null,
        "doc_url": "https://docs.openmrp.ai/api/errors#method_not_allowed",
        "is_transient": false,
        "quota": null,
        "request_log_url": "https://openmrp.ai/dashboard/request-logs/rq_fbv1ygmybo3eauykr74"
    }
}
```

Check the endpoint reference and use an allowed method for that route. In this example, items are read-only: you list, retrieve, and inspect their inventory, and you assign a category or attribute values, but you create and update the underlying record through the product, part, or material endpoints.

</ErrorDetails>

### Parameters

Parameter errors are about query string or path parameters. Body field errors use the validation codes above.

<ErrorDetails code="parameter_missing" meta="400 Bad Request, not transient">

A required query string or path parameter was not provided.

```bash
curl API_HOST/v1/core/addresses/suggestions \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "OpenMRP-Version: CURRENT_API_VERSION" \
  -H "OpenMRP-Account: YOUR_ACCOUNT_ID"
```

```json
{
    "error": {
        "code": "parameter_missing",
        "type": "invalid_request_error",
        "message": "Query parameter 'input' is required.",
        "param": "input",
        "doc_url": "https://docs.openmrp.ai/api/errors#parameter_missing",
        "is_transient": false,
        "quota": null,
        "request_log_url": "https://openmrp.ai/dashboard/request-logs/rq_fbv1ygmybo3eauykr74"
    }
}
```

Include the required parameter and make sure URL construction does not create empty path segments. The equivalent failure on a JSON body field is [`missing_field`](#missing_field) instead.

</ErrorDetails>

<ErrorDetails code="parameter_invalid" meta="400 Bad Request, not transient">

A query or path parameter was supplied, but its value is outside the allowed range or enum.

```bash
curl "API_HOST/v1/catalog/items?limit=-25" \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "OpenMRP-Version: CURRENT_API_VERSION" \
  -H "OpenMRP-Account: YOUR_ACCOUNT_ID"
```

```json
{
    "error": {
        "code": "parameter_invalid",
        "type": "invalid_request_error",
        "message": "Query parameter 'limit' must be at least 1.",
        "param": "limit",
        "doc_url": "https://docs.openmrp.ai/api/errors#parameter_invalid",
        "is_transient": false,
        "quota": null,
        "request_log_url": "https://openmrp.ai/dashboard/request-logs/rq_fbv1ygmybo3eauykr74"
    }
}
```

`limit` accepts `1`-`1000` and defaults to `100`. An unrecognized enum value in a query parameter reports the same code with `Field '<name>' must be one of: …`.

Use the ranges and enum values from the API reference. For pagination, pass back cursors exactly as OpenMRP returned them.

</ErrorDetails>

<ErrorDetails code="parameter_unknown" meta="400 Bad Request, not transient">

The request included a query parameter the endpoint does not declare. Unknown parameters are rejected rather than ignored, so a typo fails loudly instead of silently returning unfiltered results.

```bash
curl "API_HOST/v1/catalog/items?skip=50" \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "OpenMRP-Version: CURRENT_API_VERSION" \
  -H "OpenMRP-Account: YOUR_ACCOUNT_ID"
```

```json
{
    "error": {
        "code": "parameter_unknown",
        "type": "invalid_request_error",
        "message": "Unknown query parameter 'skip'.",
        "param": "skip",
        "doc_url": "https://docs.openmrp.ai/api/errors#parameter_unknown",
        "is_transient": false,
        "quota": null,
        "request_log_url": "https://openmrp.ai/dashboard/request-logs/rq_fbv1ygmybo3eauykr74"
    }
}
```

An unrecognized **JSON body** field returns the same code, with a suggestion when the name is close to a real one: `Invalid JSON in request body: unknown field 'expire_at'. Did you mean 'expires_at'?`

Remove the unknown parameter or rename it to the supported one. Cursor-based list endpoints accept `cursor`, `limit`, `q` (free-text search), `include`, and each endpoint's documented filters. **The free-text parameter is `q`, not `search`** — `?search=…` is rejected with exactly this error. Array filters accept either `key=a,b` or `key[]=a&key[]=b`.

</ErrorDetails>

<ErrorDetails code="parameters_exclusive" meta="400 Bad Request, not transient">

Reserved for a request that supplies two mutually exclusive parameters.

If it ever appears, treat it like the other parameter errors: choose one supported mode for the operation and remove the conflicting parameter. It maps to 400 and is not transient.

</ErrorDetails>

### Resources

Resource errors mean the target object is missing, duplicated, in the wrong state, or gone.

<ErrorDetails code="resource_not_found" meta="404 Not Found, not transient">

The requested resource does not exist in the target account, or the caller cannot access it.

```bash
curl API_HOST/v1/operations/shipping-terms/shtm_c5gxy05whw6r \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "OpenMRP-Version: CURRENT_API_VERSION" \
  -H "OpenMRP-Account: YOUR_ACCOUNT_ID"
```

```json
{
    "error": {
        "code": "resource_not_found",
        "type": "invalid_request_error",
        "message": "Shipping term not found.",
        "param": null,
        "doc_url": "https://docs.openmrp.ai/api/errors#resource_not_found",
        "is_transient": false,
        "quota": null,
        "request_log_url": "https://openmrp.ai/dashboard/request-logs/rq_fbv1ygmybo3eauykr74"
    }
}
```

Verify the public ID, the `OpenMRP-Account` header, and whether the resource was deleted. Never send internal database IDs to the API.

</ErrorDetails>

<ErrorDetails code="resource_exists" meta="409 Conflict, not transient">

The write violated a uniqueness constraint in storage. The public message is deliberately generic, because it is produced by the database layer rather than by the endpoint.

```bash
curl -X POST API_HOST/v1/catalog/item-categories \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "OpenMRP-Version: CURRENT_API_VERSION" \
  -H "OpenMRP-Account: YOUR_ACCOUNT_ID" \
  -H "Content-Type: application/json" \
  -d '{"name":"Electronics","type":"material_category","unit_group_id":"ug_andst6m79n41"}'
```

```json
{
    "error": {
        "code": "resource_exists",
        "type": "invalid_request_error",
        "message": "Resource already exists.",
        "param": null,
        "doc_url": "https://docs.openmrp.ai/api/errors#resource_conflict",
        "is_transient": false,
        "quota": null,
        "request_log_url": "https://openmrp.ai/dashboard/request-logs/rq_fbv1ygmybo3eauykr74"
    }
}
```

Endpoints that check uniqueness before writing return [`resource_conflict`](#resource_conflict) instead, with a field-specific message and a populated `param` — so the same logical mistake can surface under either code depending on the endpoint. Handle both.

Find and reuse the existing resource or choose a different unique value. Note that `doc_url` on this code points at `#resource_conflict`, not `#resource_exists`.

</ErrorDetails>

<ErrorDetails code="resource_conflict" meta="409 Conflict, not transient">

The request conflicts with the current state of the resource or account — most often a uniqueness rule the endpoint checks before writing.

```bash
curl -X POST API_HOST/v1/catalog/units \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "OpenMRP-Version: CURRENT_API_VERSION" \
  -H "OpenMRP-Account: YOUR_ACCOUNT_ID" \
  -H "Content-Type: application/json" \
  -d '{"name":"Gram","abbreviation":"g","type":"mass","ratio_numerator":"1","ratio_denominator":"1","offset_numerator":"0","offset_denominator":"1"}'
```

```json
{
    "error": {
        "code": "resource_conflict",
        "type": "invalid_request_error",
        "message": "A unit with this name already exists.",
        "param": "name",
        "doc_url": "https://docs.openmrp.ai/api/errors#resource_conflict",
        "is_transient": false,
        "quota": null,
        "request_log_url": "https://openmrp.ai/dashboard/request-logs/rq_fbv1ygmybo3eauykr74"
    }
}
```

Refresh the resource, inspect its current state, and submit a valid next action. When `param` is present it names the field that collides.

</ErrorDetails>

<ErrorDetails code="resource_gone" meta="410 Gone, not transient">

The resource existed previously, but has been permanently deleted or can no longer be modified. In practice you hit this by repeating a delete: the endpoint looks the resource up, does not find it, checks the deleted-record trail, and reports that it is already gone.

```bash
curl -X DELETE API_HOST/v1/catalog/products/pd_07oe0r7adh2w \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "OpenMRP-Version: CURRENT_API_VERSION" \
  -H "OpenMRP-Account: YOUR_ACCOUNT_ID"
```

```json
{
    "error": {
        "code": "resource_gone",
        "type": "invalid_request_error",
        "message": "This product has already been deleted and can no longer be modified.",
        "param": null,
        "doc_url": "https://docs.openmrp.ai/api/errors#resource_gone",
        "is_transient": false,
        "quota": null,
        "request_log_url": "https://openmrp.ai/dashboard/request-logs/rq_fbv1ygmybo3eauykr74"
    }
}
```

Remove the deleted resource from local caches and create a replacement resource if needed.

</ErrorDetails>

### Idempotency

Idempotency errors only apply to mutating requests that use an idempotency key. See <DocLink pathKey="api.idempotency">Idempotency</DocLink> for the full retry model.

<ErrorDetails code="idempotency_in_progress" meta="409 Conflict, transient">

A request with the same idempotency key is already being processed.

```bash
curl -X PATCH API_HOST/v1/operations/shipping-terms/shtm_c5gxy05whw6r \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "OpenMRP-Version: CURRENT_API_VERSION" \
  -H "OpenMRP-Account: YOUR_ACCOUNT_ID" \
  -H "Idempotency-Key: req_abc123" \
  -H "Content-Type: application/json" \
  -d '{"name":"Collect"}'
```

```json
{
    "error": {
        "code": "idempotency_in_progress",
        "type": "idempotency_error",
        "message": "Request for the idempotency key 'req_abc123' is already being processed.",
        "param": null,
        "doc_url": "https://docs.openmrp.ai/api/errors#idempotency_in_progress",
        "is_transient": true,
        "quota": null,
        "request_log_url": "https://openmrp.ai/dashboard/request-logs/rq_fbv1ygmybo3eauykr74"
    }
}
```

Retry the same request with the same key after a short delay. Do not generate a new key unless you intend to start a separate operation.

If the same key is reused with different parameters, OpenMRP returns `validation_failed`
with `type: "idempotency_error"`:

```json
{
    "error": {
        "code": "validation_failed",
        "type": "idempotency_error",
        "message": "Idempotency key 'req_abc123' was used with different request parameters; use a new key.",
        "param": null,
        "doc_url": "https://docs.openmrp.ai/api/errors#validation_failed",
        "is_transient": false,
        "quota": null,
        "request_log_url": "https://openmrp.ai/dashboard/request-logs/rq_fbv1ygmybo3eauykr74"
    }
}
```

For the non-transient mismatch case, resend the original request exactly or use a new key for the new operation.

</ErrorDetails>

### Rate Limiting

Rate limiting is temporary throttling. See <DocLink pathKey="api.rateLimiting">Rate Limiting</DocLink> for guidance on request pacing.

<ErrorDetails code="rate_limit_exceeded" meta="429 Too Many Requests, transient">

The caller sent requests faster than OpenMRP allows.

```bash
curl API_HOST/v1/catalog/items \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "OpenMRP-Version: CURRENT_API_VERSION" \
  -H "OpenMRP-Account: YOUR_ACCOUNT_ID"
```

```json
{
    "error": {
        "code": "rate_limit_exceeded",
        "type": "invalid_request_error",
        "message": "Too many requests. Please try again later.",
        "param": null,
        "doc_url": "https://docs.openmrp.ai/api/errors#rate_limit_exceeded",
        "is_transient": true,
        "quota": null,
        "request_log_url": "https://openmrp.ai/dashboard/request-logs/rq_fbv1ygmybo3eauykr74"
    }
}
```

The response carries `Retry-After` (seconds), plus `RateLimit-Limit`, `RateLimit-Remaining`, and `RateLimit-Reset`. `Retry-After` grows with each successive violation, so hammering the endpoint makes the wait longer.

Back off before retrying, honor `Retry-After`, and add client-side queueing or rate limiting if your integration bursts above the limit.

</ErrorDetails>

### API Version

API version errors are fixed by sending a supported `OpenMRP-Version` header. See <DocLink pathKey="api.versioning">API Versioning</DocLink> for supported versions and upgrade guidance.

<ErrorDetails code="api_version_required" meta="400 Bad Request, not transient">

The request did not include the required `OpenMRP-Version` header.

```bash
curl API_HOST/v1/catalog/items \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "OpenMRP-Account: YOUR_ACCOUNT_ID"
```

```json
{
    "error": {
        "code": "api_version_required",
        "type": "invalid_request_error",
        "message": "The OpenMRP-Version header is required. Please include a valid API version. The latest version is CURRENT_API_VERSION.",
        "param": null,
        "doc_url": "https://docs.openmrp.ai/api/errors#api_version_required",
        "is_transient": false,
        "quota": null,
        "request_log_url": "https://openmrp.ai/dashboard/request-logs/rq_fbv1ygmybo3eauykr74"
    }
}
```

Add `OpenMRP-Version` to every request or configure it once in your SDK client.

</ErrorDetails>

<ErrorDetails code="api_version_invalid" meta="400 Bad Request, not transient">

The `OpenMRP-Version` header is present, but the value is not one OpenMRP serves. This covers both a malformed string and a well-formed version that is no longer (or not yet) supported — OpenMRP versions are named, not dated, so a date is always rejected here.

```bash
curl API_HOST/v1/catalog/items \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "OpenMRP-Version: 2024-01-01" \
  -H "OpenMRP-Account: YOUR_ACCOUNT_ID"
```

```json
{
    "error": {
        "code": "api_version_invalid",
        "type": "invalid_request_error",
        "message": "Invalid API version '2024-01-01'. Supported versions: [CURRENT_API_VERSION 1.0.forge-preview.1]",
        "param": null,
        "doc_url": "https://docs.openmrp.ai/api/errors#api_version_invalid",
        "is_transient": false,
        "quota": null,
        "request_log_url": "https://openmrp.ai/dashboard/request-logs/rq_fbv1ygmybo3eauykr74"
    }
}
```

The `message` always lists every currently supported version, so it is the authoritative answer even when this page is stale. Use one of those values, or see the versioning guide.

</ErrorDetails>

<ErrorDetails code="api_version_too_old" meta="400 Bad Request, not transient">

Reserved for an endpoint that requires a newer API version than the request asked for.
If it appears, the message names both the minimum the endpoint needs and the version you sent — `This endpoint requires API version CURRENT_API_VERSION or newer. You requested 1.0.forge-preview.1.` Upgrade the version for that integration after testing compatibility.

</ErrorDetails>

### Server Errors

Server errors mean OpenMRP or a dependency failed while handling the request. Most are transient. For mutating requests, retry with the same idempotency key.

<ErrorDetails code="internal_error" meta="500 Internal Server Error, transient">

OpenMRP encountered an unexpected server-side failure. The public message is intentionally generic; internal diagnostics are captured in OpenMRP logs.

```bash
curl API_HOST/v1/catalog/items \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "OpenMRP-Version: CURRENT_API_VERSION" \
  -H "OpenMRP-Account: YOUR_ACCOUNT_ID"
```

```json
{
    "error": {
        "code": "internal_error",
        "type": "api_error",
        "message": "Something went wrong.",
        "param": null,
        "doc_url": "https://docs.openmrp.ai/api/errors#internal_error",
        "is_transient": true,
        "quota": null,
        "request_log_url": "https://openmrp.ai/dashboard/request-logs/rq_fbv1ygmybo3eauykr74"
    }
}
```

Retry with exponential backoff if the operation is safe to retry. If it persists, include `request_log_url` when contacting OpenMRP support.

</ErrorDetails>

<ErrorDetails code="service_unavailable" meta="503 Service Unavailable, transient">

Reserved for an OpenMRP service or internal dependency being temporarily unavailable.

</ErrorDetails>

<ErrorDetails code="external_service_error" meta="502 Bad Gateway, transient">

Reserved for a third-party service used by OpenMRP returning an error.

</ErrorDetails>

<ErrorDetails code="timeout" meta="504 Gateway Timeout, transient">

Reserved for an operation exceeding a deadline while OpenMRP waits for work to finish.

</ErrorDetails>

<ErrorDetails code="connection_error" meta="502 Bad Gateway, transient">

Reserved for a network-level failure reaching a service OpenMRP depends on.

</ErrorDetails>

<ErrorDetails code="request_timeout" meta="504 Gateway Timeout, transient">

An internal call exceeded its deadline before OpenMRP could finish processing the request. Long-running analytical or planning work is the usual cause.

```bash
curl -X PUT API_HOST/v1/operations/production-schedules/actions/preview \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "OpenMRP-Version: CURRENT_API_VERSION" \
  -H "OpenMRP-Account: YOUR_ACCOUNT_ID" \
  -H "Content-Type: application/json" \
  -d '{"horizon_weeks":104}'
```

```json
{
    "error": {
        "code": "request_timeout",
        "type": "api_error",
        "message": "Request timed out.",
        "param": null,
        "doc_url": "https://docs.openmrp.ai/api/errors#request_timeout",
        "is_transient": true,
        "quota": null,
        "request_log_url": "https://openmrp.ai/dashboard/request-logs/rq_fbv1ygmybo3eauykr74"
    }
}
```

Retry with backoff. For long-running operations, narrow the request (a shorter planning horizon, a tighter date range, a smaller `limit`) and use idempotency keys on mutations.

</ErrorDetails>

<ErrorDetails code="client_closed_request" meta="499, not transient">

The client disconnected before OpenMRP finished processing the request. Status `499` is a non-standard HTTP status commonly used by proxies for client-closed requests. OpenMRP still writes the status and the request log, so the call is visible even though nothing reached your client.

```bash
curl --max-time 2 -X POST API_HOST/v1/sales/sales-orders/or_9lqo07quiwyb/actions/create-production-run \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "OpenMRP-Version: CURRENT_API_VERSION" \
  -H "OpenMRP-Account: YOUR_ACCOUNT_ID" \
  -H "Idempotency-Key: req_create_run_01"
```

```json
{
    "error": {
        "code": "client_closed_request",
        "type": "api_error",
        "message": "Client closed the connection.",
        "param": null,
        "doc_url": "https://docs.openmrp.ai/api/errors#client_closed_request",
        "is_transient": false,
        "quota": null,
        "request_log_url": "https://openmrp.ai/dashboard/request-logs/rq_fbv1ygmybo3eauykr74"
    }
}
```

A cancellation that surfaces from the database layer instead reports `Request was canceled.` under the same code.

**The work may still have completed.** A 499 says your client went away, not that OpenMRP stopped. Investigate client-side cancellation, browser navigation, network interruption, or a proxy or client timeout that is shorter than the operation. For mutations, always send an idempotency key so the retry cannot duplicate work that already landed.

</ErrorDetails>

## Retry Behavior

Errors with `"is_transient": true` may resolve on retry:

| Type                    | Transient codes                                                                                                     |
| ----------------------- | ------------------------------------------------------------------------------------------------------------------- |
| `api_error`             | `internal_error`, `service_unavailable`, `external_service_error`, `timeout`, `connection_error`, `request_timeout` |
| `idempotency_error`     | `idempotency_in_progress`                                                                                           |
| `invalid_request_error` | `rate_limit_exceeded`                                                                                               |
