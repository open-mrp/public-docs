OpenMRP API URIs follow a consistent format:

[https](#protocol)://[api.openmrp.ai](#host)/[v1](#version)/[sales](#application-domain)/[customers](#resource)/[ac_0z28u55ruj0q](#resource-identifier)

### Protocol

The protocol defines the communication method and security level. All OpenMRP API endpoints use `https`, which encrypts data using TLS/SSL. This ensures that all API requests and responses are protected from interception and tampering. Any request without TLS will be rejected outright.

### Host

The host identifies the server that will process your request. Currently, all public endpoints are available from `api.openmrp.ai`. If you inspect the network of the Dashboard, you will notice that some requests target a different base URL `legacy-api.openmrp.ai`. We are currently migrating many endpoints that were in private preview to the new base URL. These endpoints should be considered deprecated and are not stable for public use. Should you require a particular endpoint that you find in the legacy API, please contact us and we will be happy to assist you.

### Version

The version specified in the URI is separate from the semantic versioning of the API. In general, you can consider this version stable at `v1`. We set a very high bar for introducing new major versions of the API and expect `v1` to be stable for many years to come. The version appears immediately after the host in the URI path, such as `/v1/`.

### Application Domain

The application domain is the functional area that the endpoint belongs to. It appears immediately after the version in the URI path and groups endpoints by the part of the business they serve. The public API uses these domains:

| Domain       | What lives there                                                                       |
| ------------ | -------------------------------------------------------------------------------------- |
| `auth`       | API keys and key rotation                                                              |
| `catalog`    | Items, products, parts, materials, categories, properties, units and unit groups       |
| `core`       | Addresses, search, analytics, sandboxes, request logs, audit events, email logs        |
| `finance`    | Payment terms, transaction and adjustment types                                        |
| `identity`   | Accounts, account users and roles                                                      |
| `messaging`  | Conversations, messages, notifications, announcements, email domains and inboxes       |
| `operations` | Locations, carriers, scanning stations, machines, production schedules, shipping terms |
| `sales`      | Customers, contacts, sales orders, account groups, statuses and priorities             |
| `settings`   | Integrations and portal domains                                                        |

The domain tells you which product area an endpoint belongs to; it is not necessarily a policy boundary.

### Resource

The resource is the main entity that the API is interacting with. Resources are typically plural nouns that represent collections of similar items, such as `customers`, `sales-orders`, `products`, or `account-users`. Multi-word resources are hyphenated, never underscored.

### Resource identifier

The resource identifier uniquely identifies a specific resource within a collection. It's usually a type ID. For example, `.../customers/ac_0z28u55ruj0q` identifies customer ac_0z28u55ruj0q. The resource identifier appears after the resource name in the URI path.

### Actions

Generally, we utilize the standard HTTP methods to interact with resources. However, on occasion there are actions that cannot be represented easily with a standard HTTP method. In these cases, we provide a sub-resource to represent actions.

For example, `POST /v1/sales/customers/ac_0z28u55ruj0q/actions/merge` merges another customer into customer ac_0z28u55ruj0q. Here `actions` is the resource segment and `merge` is the sub-resource naming the verb. Each action gets its own path — actions are never multiplexed behind a `type` field in the body.
