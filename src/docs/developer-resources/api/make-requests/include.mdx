API responses that contain sub-objects (such as `role` on an API key, or `account` on a request log) return **`null`** by default. To get full sub-object data, use the `include` query parameter.

## Default behavior

Without `include`, sub-objects are `null`:

```json
{
    "id": "apke_eiylmwr6q7oz",
    "object": "api_key",
    "name": "Production API Key",
    "role": null
}
```

## Expanding sub-objects

Pass `include` as a query parameter to expand specific sub-objects. Two spellings are supported, and they are equivalent:

**Array-style (recommended):**

```bash
curl "API_HOST/v1/auth/api-keys/apke_eiylmwr6q7oz?include[]=role" \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "OpenMRP-Version: CURRENT_API_VERSION"
```

**Comma-separated:**

```bash
curl "API_HOST/v1/auth/api-keys/apke_eiylmwr6q7oz?include=role" \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "OpenMRP-Version: CURRENT_API_VERSION"
```

Both forms accept repetition **and** comma-separated lists, and the two can be mixed in a single request. All of these request the same two expansions:

```
?include[]=account&include[]=actor.role
?include[]=account,actor.role
?include=account,actor.role
?include=account&include[]=actor.role
```

With `include[]=role`, the sub-object is fully populated:

```json
{
    "id": "apke_eiylmwr6q7oz",
    "object": "api_key",
    "name": "Production API Key",
    "role": {
        "id": "rl_3xknmfqflhvb",
        "object": "role",
        "name": "Admin",
        "type": "admin"
    }
}
```

Each endpoint declares its own allow-list of include values. The accepted values for a given endpoint are enumerated on its page in the <InternalLink text="API reference" pathKey="apiReference.root" />.

## Dot-notation for nested sub-objects

Some include values use dot-notation to target a sub-object nested inside another object. For example, `actor.role` expands the `role` field within the `actor` object on a request log:

```bash
curl "API_HOST/v1/core/request-logs/rq_0lhl3kkhme40?include[]=account&include[]=actor.role" \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "OpenMRP-Version: CURRENT_API_VERSION"
```

```json
{
    "id": "rq_0lhl3kkhme40",
    "object": "request_log",
    "actor": {
        "id": "us_43irtlt2ajz6",
        "object": "actor",
        "type": "user",
        "name": "John Doe",
        "role": {
            "id": "rl_3xknmfqflhvb",
            "object": "role",
            "name": "Admin",
            "type": "admin"
        }
    }
}
```

Nesting is resolved level by level, and a deeper path implies the shallower ones — asking for `actor.role` also expands `actor`. Dot paths can go more than two levels deep where an endpoint allows it; for example, a sales order accepts `lines.product.item.category`.

## List responses

The `include` parameter applies to every item in a list response:

```bash
curl "API_HOST/v1/auth/api-keys?include[]=role" \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "OpenMRP-Version: CURRENT_API_VERSION"
```

```json
{
    "object": "list",
    "data": [
        {
            "id": "apke_eiylmwr6q7oz",
            "object": "api_key",
            "name": "Key One",
            "role": {
                "id": "rl_3xknmfqflhvb",
                "object": "role",
                "name": "Admin",
                "type": "admin"
            }
        },
        {
            "id": "apke_6p4z57e9alaf",
            "object": "api_key",
            "name": "Key Two",
            "role": {
                "id": "rl_c5gxy05whw6r",
                "object": "role",
                "name": "Warehouse",
                "type": "user"
            }
        }
    ],
    "page_info": { "...": "..." }
}
```

Without `include[]=role`, each `role` in the list would be `null`.

## Create and rotate responses

For create and rotate endpoints, the response wraps the resource in `api_key_info` alongside the secret. The `include` parameter expands sub-objects within `api_key_info`:

```bash
curl -X POST "API_HOST/v1/auth/api-keys?include[]=role" \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "OpenMRP-Version: CURRENT_API_VERSION" \
  -H "Content-Type: application/json" \
  -d '{"name": "Production Key", "role_id": "rl_3xknmfqflhvb"}'
```

```json
{
    "object": "created_api_key",
    "api_key_secret": "mrp_sk_prod_...",
    "api_key_info": {
        "id": "apke_eiylmwr6q7oz",
        "object": "api_key",
        "name": "Production Key",
        "role": {
            "id": "rl_3xknmfqflhvb",
            "object": "role",
            "name": "Admin",
            "type": "admin"
        }
    }
}
```

## Error handling

### Invalid include value

An include value that is not on the endpoint's allow-list is rejected with a `400` before the endpoint runs. The message lists every value that endpoint accepts:

```json
{
    "error": {
        "code": "parameter_invalid",
        "type": "invalid_request_error",
        "message": "Invalid include value 'invalid'. Allowed values: role, role.permissions",
        "param": "include[]",
        "doc_url": "https://docs.openmrp.ai/api/errors#parameter_invalid",
        "is_transient": false,
        "quota": null,
        "request_log_url": "https://openmrp.ai/dashboard/request-logs/rq_fbv1ygmybo3eauykr74"
    }
}
```

Note that the `param` is reported as `include[]` regardless of which spelling you sent.

### Include on an unsupported endpoint

Endpoints that have no expandable sub-objects reject the parameter entirely:

```json
{
    "error": {
        "code": "parameter_invalid",
        "type": "invalid_request_error",
        "message": "This endpoint does not support the include parameter.",
        "param": "include[]",
        "doc_url": "https://docs.openmrp.ai/api/errors#parameter_invalid",
        "is_transient": false,
        "quota": null,
        "request_log_url": "https://openmrp.ai/dashboard/request-logs/rq_fbv1ygmybo3eauykr74"
    }
}
```
